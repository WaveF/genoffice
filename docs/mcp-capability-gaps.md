# MCP 能力缺口清单

本清单记录下线内置 AI 时发现的“内置 AI 已具备、外部 MCP 尚未提供等价受控能力”。这些项目不应重新引入内置模型调用；应由外部 Agent 完成推理、搜索或生成，GenOffice 只补充受限的文档能力。

| ID     | 能力缺口                      | 当前情况                                                                                                                         | 后续方向                                                                                                                                                                                                                                                                                                          | 状态   |
| ------ | ----------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| MED-01 | 外部 Agent 生成图片后插入文档 | PDF 可通过受限 base64 `insert_image` 插入小图片；Slides 拒绝 bytes/path/source，Docs、Markdown、Sheets 未公开图片插入 MCP 工具。 | 首期由第 5 阶段的 `MD-04` 为 Markdown 建立系统临时目录下的随机私有 `mediaImportDirectory`：Agent 先将图片写入该目录，bridge 校验后复制到文档同级 `assets/`，再以 opaque handle 插入。之后复用该导入域扩展 Slides 等编辑器；禁止任意路径、URL 和 bytes。URL 下载如有需要，另行设计下载限额、域名策略与 SSRF 防护。 | 未开始 |

## 处理原则

- 不因能力缺口恢复 `agent-core`、`ai-provider`、Genspark 登录、云搜索或云图像生成。
- 每项能力须独立定义输入大小、MIME 白名单、文件生命周期、审计字段和目标文档范围。
- 新能力应优先服务已认证的本机 MCP bridge，并继续使用 opaque documentId、revision 与 renderer/main 双层校验。
- 临时目录由 GenOffice 在系统临时目录下创建并在 bridge discovery 中公布；它是本会话唯一允许 Agent 写入的导入来源，不能用任意系统临时路径替代。
